# 个人网站功能台账（Feature Ledger）

> 本文用 **MoSCoW 法**（Must / Should / Could / Won't）对个人网站 `luowenpeng.com` 做一次功能盘点：对照 2026 年同类产品的**市场通有功能基准**，标出本站**已有能力**与**用户需求但尚未实现**的缺口，并给出优先级路线图。
>
> 所有判断都先过一遍**第〇原则**——见下。

---

## 〇、第〇原则：足够好看（Foundation）

> **第〇原则优先于一切 MoSCoW 判定。** 一个功能再"应该做"，如果会伤害"好看"，就要降级或换更克制的实现；一个功能再"不会做"，如果它是好看的根基（速度、留白、字体、对比度），就是 Must。

"好看"在本站具体拆成五条可判定的子原则：

1. **快**——慢等价于不好看（LCP < 2.5s、CLS < 0.1 是 2026 硬指标）。
2. **净**——极简留白、信息层级清晰，不堆砌按钮与部件。
3. **读**——排版舒适（正文行高、字号、字体层级）、深浅双主题。
4. **一**——视觉有统一识别（配色、格言、字体气质），不杂乱。
5. **容**——无障碍（对比度、alt、键盘可达）是"对所有人好看"。

---

## 一、MoSCoW 口径

| 等级 | 含义 | 本站判定习惯 |
|------|------|--------------|
| **Must** | 没有它站点就失格（违背第〇原则或核心用途） | 速度/SEO/可达性/断链体验的基础项 |
| **Should** | 高价值、用户普遍期待，应尽快做 | 分享、归档、阅读细节、结构化数据 |
| **Could** | 锦上添花、可 delight，但不紧急 | 微交互、PWA、Now 页、灯箱 |
| **Won't** | 现阶段明确不做（与定位冲突或过度） | 广告、登录、AI 客服、重客户端渲染 |

---

## 二、市场通有功能基准（2026，来自行业调研）

调研 2026 年个人网站 / 博客最佳实践，同类产品**普遍具备**的能力可归为六类：

- **视觉与舒适**：极简留白布局、粗体排版、深色模式切换（已从"潮流"变为"标配"）、移动优先响应式、微交互（克制 hover / 滚动动效）。
- **性能与 SEO**：极速加载（Core Web Vitals）、XML sitemap、OG / Twitter 卡片、结构化数据（JSON-LD）、语义化标题、图片优化与懒加载、"最后修改"日期。
- **导航与结构**：站内搜索、关于页、联系方式、文章归档 / 索引、标签 / 分类、自定义 404、隐私政策页、新访客引导（Start Here）。
- **互动与留存**：RSS、相关阅读、社交分享按钮、评论系统（Giscus 等隐私友好方案）、邮件订阅、阅读时长、阅读进度条。
- **统计与信任**：隐私友好统计（Plausible / GoatCounter / Umami）、内容许可声明。
- **进阶 / IndieWeb**：无障碍审计、图片灯箱、PWA / 离线、Webmention、Now 页、留言板、多语言。

> 关键趋势：**深色模式、隐私统计、结构化数据、无障碍**在 2026 已从"加分项"转为"预期项"；纯 Google Analytics + 无深色模式 + 无 404 的站点会被视为"不够现代"。

## 三、当前站点能力盘点（luowenpeng.com 现状）

已具备（✅）：SSG 静态极速、响应式、深色切换（VitePress 默认）、极简留白排版、Noto Serif SC 标题层级、OG/Twitter 卡片 + og:image、自动 sitemap、local 搜索、关于页、邮箱联系、RSS（自建）、相关阅读、GoatCounter 隐私统计、TOC、回到顶部、CC 许可、KaTeX、代码高亮、lastUpdated。

## 五、用户需求但尚未实现（Gaps）

> 这里的"用户需求"指：从第〇原则推导的必然需求 + 行业普遍期待 + 本站内容形态（长文/数据/周报）带来的特定需求。

1. **断链兜底（404 页）**——任何站点都躲不开的死链场景，当前缺失，是最该立刻补的 Must。
2. **无障碍基线**——含图片 alt、对比度复核、键盘导航；既是 2026 预期项，也是"对所有人好看"。
3. **文章归档 / 全量索引**——本站文章已 10+ 篇且持续增长（城轨周报周更），仅靠 nav 下拉会迅速臃肿；需要一个按时间/分组的归档页。
4. **结构化数据**——长文 + 城轨周报都是被搜索引擎/AI 摘要抓取的好素材，缺 JSON-LD 等于放弃富媒体呈现。
5. **社交分享 + 阅读时长**——低成本的"好看体验细节"，当前为零。
6. **隐私政策页**——即便用 GoatCounter（无 Cookie），一份简洁隐私说明仍能提升信任（E-E-A-T 信号）。
7. **视觉记忆点强化**——格言与蓝灰配色已有识别，但 hero / 关于页可再有克制的人格化表达（微交互或轻叙事）。
8. **评论或留言板**（待定）——用户未明确要，但"个人站 + 行业周报"有讨论价值；若做，优先 Giscus 或 Guestbook，避免 Disqus 追踪破坏"净"。

## 六、建议路线图（按 MoSCoW 分期）

### 第一阶段 · Must（先补齐"失格项"，直接护住第〇原则）
- [ ] 自定义 404 页（`docs/404.md` → `404.html`）
- [ ] 无障碍基线：补图片 alt、复核对比度（≥4.5:1）、键盘可达性自查
- [ ] 图片显式优化：width/height 防 CLS、关键图懒加载、hero-bg 压缩
- [ ] 结构化数据 JSON-LD（Article + Breadcrumb）注入

### 第二阶段 · Should（拉齐"市场普遍期待"）
- [ ] 文章归档 / 索引页（替代膨胀的 nav 下拉，可基于 frontmatter 自动聚合）
- [ ] 社交分享按钮（每页 2–3 平台，克制）
- [ ] 阅读时长估算
- [ ] 隐私政策页
- [ ] 视觉识别强化（hero/关于页轻量人格化）

### 第三阶段 · Could（锦上添花，按精力投放）
- [ ] 微交互（hover/滚动，克制）
- [ ] 阅读进度条 / 灯箱
- [ ] PWA / 离线
- [ ] Now 页 / 留言板（替代或补充评论）
- [ ] 打印样式

### 明确不做
- 广告、登录会员、AI 客服、语音搜索、客户端渲染 SPA、多语言（现阶段）。

## 七、权衡提醒

- **好看 ≠ 功能多**。每加一个部件都要问："它让页面更净了，还是更挤了？" 评论、分享、订阅若堆一起，反而伤第〇原则。
- **SSG 是好看的地基**：速度即好看，Won't 列表里的客户端渲染、重框架都守住不碰。
- **先做 Must 再谈 Should**：404、无障碍、结构化数据这三件"看不见但失格"的项，优先级高于任何炫酷微交互。
- **数据类内容（客流/周报）天然适合"可发现 + 可订阅"**：RSS 已具备，结构化数据 + 归档页是它们被搜到的关键杠杆。
